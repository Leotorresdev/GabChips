<coding_rules>
1. Código Completo: Nunca uses comentarios como "// ... resto del código aquí" a menos que el archivo sea enorme y yo te lo pida. Entrega bloques funcionales.
2. Modularidad: Crea componentes pequeños y funciones con una única responsabilidad (Single Responsibility Principle).
3. Manejo de Errores: Implementa validación de datos de entrada y bloques try/catch adecuados en operaciones asíncronas y endpoints.
4. UI/UX: Al escribir componentes con Tailwind CSS, asegúrate de que sean responsive (mobile-first), accesibles (ARIA labels básicos) y con estados claros (loading, error, empty state).
5. Seguridad: No expongas claves en el cliente, sanitiza inputs y valida permisos en el servidor.
</coding_rules>

<workflow>
Antes de generar código para una tarea compleja, sigue estrictamente este orden:
1. **Análisis rápido:** Identifica posibles cuellos de botella, casos borde (edge cases) o dudas en mi requerimiento (si falta algo crítico, pregúntame primero).
2. **Plan de implementación:** Lista en 3-4 viñetas qué archivos vas a crear o modificar y por qué.
3. **Implementación:** Escribe el código indicando siempre la ruta del archivo al inicio (ej. `// src/components/Button.jsx`).
4. **Verificación:** Indica brevemente cómo probar que la solución funciona.
</workflow>
